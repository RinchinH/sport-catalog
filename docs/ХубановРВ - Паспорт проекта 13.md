| Поле | Значение |
|---|---|
| Название проекта | СпортКаталог |

Покупатель может просматривать товары, оформлять заказы, смотреть свою историю покупок, скачивать её в виде таблицы и просматривать график покупок. ## 2. Проблема

Покупателю важно видеть, какие спортивные товары есть в наличии, и удобно оформлять заказы. Продавцу нужно учитывать поступления товаров и их остатки на складе. Если два покупателя одновременно пытаются заказать последний товар, система должна продать его только одному из них.

**Решение:** создать сайт с каталогом спортивных товаров, личным кабинетом покупателя и простым управлением складом для администратора. Сайт будет автоматически уменьшать остаток после успешной покупки и не позволит оформить заказ на отсутствующий товар.

## 3. Пользовательские сценарии (user stories)

| Роль | Что делает |
|---|---|
| Гость | Просматривает каталог спортивных товаров, цены и остатки. |
| Гость | Регистрируется и входит на сайт. |
| Покупатель | Выбирает товар и его количество, оформляет заказ. |
| Покупатель | Получает сообщение, если нужного количества уже нет в наличии. |
| Покупатель | Просматривает только свои заказы. |
| Покупатель | Скачивает список своих заказов в CSV-файле для Excel. |
| Покупатель | Смотрит график количества заказанных товаров. |
| Покупатель | Скачивает график в формате PNG. |
| Администратор | Входит в систему с правами администратора. |
| Администратор | Просматривает список товаров и их остатки на складе. |
| Администратор | Добавляет новый спортивный товар в каталог. |
| Администратор | Регистрирует поступление товара на склад, увеличивая его количество. |

**Пример одновременной покупки:** на складе остался один футбольный мяч. Два покупателя открыли страницу и одновременно нажали «Купить». Если заказ первого покупателя прошёл успешно, второму сайт покажет сообщение «Товар закончился», а его заказ не будет создан. Остаток не станет отрицательным.

## 4. Функциональные требования

| ID | Требование | Как проверить (критерий приёмки) |
|---|---|---|
| FR-0 | Проект запускается одной командой `docker compose up -d`. | После запуска доступны сайт, сервер и база данных. |
| FR-1 | Пользователь может зарегистрироваться и войти по логину и паролю. | Правильный пароль позволяет войти и получить токен; неверный пароль вызывает ошибку 401. При обычной регистрации создаётся покупатель, а не администратор. |
| FR-2 | Покупатель видит только свои заказы. | При входе под разными аккаунтами отображаются разные заказы; запрос чужого заказа не даёт доступа к нему. |
| FR-3 | На сайте отображается каталог спортивных товаров. | Видны название, цена и актуальное количество каждого товара. |
| FR-4 | Покупатель может оформить заказ. | При наличии нужного количества создаётся заказ, а остаток товара уменьшается на купленное количество. Если товара недостаточно, заказ не создаётся. |
| FR-5 | Покупатель может скачать историю своих заказов в CSV. | Скачивается файл с названиями товаров, количеством и стоимостью; чужие заказы в файл не попадают. |
| FR-6 | Покупатель может посмотреть график своих покупок. | Появляется столбчатый график с товарами и суммарным количеством купленных единиц. При отсутствии покупок появляется сообщение вместо пустого графика. |
| FR-7 | Покупатель может скачать график. | После нажатия кнопки «Скачать график» сохраняется файл PNG. |
| FR-8 | В системе есть две роли: покупатель и администратор. | Администратор видит страницу управления товарами. Обычный пользователь не видит её и получает ошибку 403 при попытке вызвать административный API. |
| FR-9 | Администратор может добавлять товары и оформлять поступление товара. | Новый товар появляется в каталоге. Если на складе было 4 мяча и администратор добавил поступление ещё 6, остаток становится 10. Указать нулевое или отрицательное поступление нельзя. |
| FR-10 | Остаток товара учитывается автоматически. | Если на складе было 10 мячей, после заказа 3 штук остаётся 7. При попытке заказать 8 штук заказ отклоняется, остаток остаётся 7. |
| FR-11 | Система не позволяет продать один и тот же последний товар двум покупателям одновременно. | Для товара с остатком 1 одновременно отправляются два заказа от разных покупателей. Успешным становится ровно один заказ, второй получает ошибку 409 и сообщение о нехватке товара. В базе остаётся 0 штук, а не −1. |
